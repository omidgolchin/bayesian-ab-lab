# PLAN — Bayesian A/B Lab (P14)

Frozen before the LLM-check main run. The frozen file list and hashes are
in `FREEZE_MANIFEST.txt`. Anything that changes the numbers changes this
plan and the manifest first, with the change logged in `DECISIONS.md`.

## What this project is

A learner's lab for reading A/B tests two ways — the classic
frequentist read and the Bayesian read — built to understand where each
one misleads. It has four parts: a calculator that puts the two reads
side by side, a simulator of what happens when you peek at a running
test, an analysis of a real published A/B test (Cookie Cats) done both
ways, and a check of whether a language model reads A/B results
correctly when it answers directly versus when it writes the code.

Framing, fixed in advance: this is a learning tool built on classic
methods. It claims no novelty. The Bayesian machinery is the standard
Beta-binomial treatment in Gelman et al.; the peeking analysis follows
the repeated-significance-testing literature going back to Armitage,
McPherson & Rowe (1969). The LLM check follows this portfolio's shared
pattern — Direct vs Code — with the calculator in this repo as ground
truth.

## The calculator

- Classic read: difference in proportions, Wald 95% confidence interval
  (unpooled standard error), two-sided p-value from the pooled
  two-proportion z-test.
- Bayesian read: independent Beta(α, β) priors on the two rates, default
  (1, 1), user-changeable in the playground. Reported: posterior means
  and 95% credible intervals per arm, P(B beats A), the expected loss of
  choosing A and of choosing B, and a 95% credible interval for the
  difference.
- Computation: exact formulas (integer-parameter series for P(B beats A),
  quadrature for expected losses, the exact difference CDF for the
  credible interval) for total samples up to 2,000; a fitted-grid
  computation above that, checked against the exact formulas and against
  Monte Carlo in the tests.
- The plain-language sentences under each read are generated by rules
  from the numbers (thresholds on the p-value, probability, and losses),
  never by a language model.
- Documented check case: A 10/100 vs B 20/100 → difference +10.00
  points, p ≈ 0.0477, P(B beats A) between 0.95 and 0.99.

## The decision rule (ground truth for the LLM check)

Fixed here, before any model output is seen:

- **ship_b** if P(B beats A) ≥ 0.95 **and** expected loss of choosing B
  ≤ 0.002 (0.2 points);
- **ship_a** if P(B beats A) ≤ 0.05 **and** expected loss of choosing A
  ≤ 0.002;
- **keep_testing** otherwise.
- Override: for an item whose team stopped the test because it turned
  significant (the "peeked" items), the correct decision is always
  **keep_testing**, whatever the final numbers say.

## The peeking simulator

- Identical arms, true rate 10% each; visitors arrive in blocks of 250
  per arm; the accumulating data are checked after every block, up to 40
  looks (10,000 visitors per arm); 5,000 simulated tests, seed 20261112.
- Classic rule: stop at the first look with two-sided p < 0.05.
- Bayesian rule: stop at the first look where the expected loss of
  shipping the current leader falls below 0.0005 (0.05 points).
- Reported honestly: the false-positive rate of **both** rules as a
  function of the number of looks. The Bayesian rule is expected to
  inflate too — a fixed loss threshold with unlimited looks still
  manufactures confident wrong answers — and the summary says so.
- Sanity anchors: with exactly one look the classic rate must be 5%
  within Monte Carlo error (tested); Armitage, McPherson & Rowe (1969)
  tabulated 5.0% / 8.3% / 14.2% / 19.3% / 24.6% for 1 / 2 / 5 / 10 / 20
  equally spaced looks in the normal case, and the binomial simulation
  should land in that neighbourhood.
- The fix, presented alongside: a sample size fixed in advance from a
  power calculation. Reference case: +2 points on a 10% base rate, 80%
  power, α = 0.05 → ≈ 3,838 visitors per arm (computed by
  `required_n_per_arm`, tested against the textbook range).

## Adaptive allocation (secondary tab)

- Thompson sampling vs a fixed 50/50 split, 2,000 simulated tests of
  4,000 visitors, seed 20261112. Two scenarios: true rates 10% vs 12%,
  and no difference (10% vs 10%).
- Reported: mean conversions, regret against the always-best-arm
  oracle, and how often the final Bayesian read is confident (≥ 95%)
  and right / confident and wrong. The expected trade — more
  conversions during the test, weaker evidence after it — is reported
  whichever way the numbers land.

## Cookie Cats analysis

- Data: see `DATA_SOURCES.md`. License listed as "Unknown" on Kaggle,
  so the CSV is **not** redistributed: `scripts/download_data.py`
  fetches it (Kaggle API, falling back to the dataset author's GitHub
  mirror) and verifies the shape (90,189 rows; gate_30 n = 44,700;
  gate_40 n = 45,489) before use. Only derived results are published.
- Comparisons: gate_30 (A) vs gate_40 (B) for 1-day and 7-day
  retention, each read classically and Bayesianly, plus a bootstrap
  percentile confidence interval for the difference (20,000 resamples,
  seed 20261112) as a distribution-free check.

## The LLM check

- **Items:** 30 fixed A/B summaries written by hand
  (`src/bayesab/items.py`): 8 clear B wins, 4 clear A wins, 6
  large-sample ties, 5 small samples, 4 peeked results, 3 borderline.
  Each item is counts plus a one-paragraph story; the numbers are the
  whole item.
- **Modes:** Direct — the model answers with a decision, a probability
  that B is better, and a concerns sentence, as JSON. Code — the model
  writes Python that computes P(B beats A) and the p-value; the code
  runs in a subprocess sandbox (scrubbed environment, 60 s timeout,
  network namespace isolation where available) and its printed JSON is
  scored. Prompts are frozen in `prompts/direct.md` and
  `prompts/code.md`.
- **Scoring** (`src/bayesab/score.py`), fixed in advance:
  - format: the reply parses / the code runs and prints the required
    JSON. Failures are reported, never dropped.
  - decision: exact match with the ground-truth rule above. In code
    mode the decision is derived from the computed probability only
    (ship B ≥ 0.95, ship A ≤ 0.05, else keep testing), and peeked items
    are not decision-scored in code mode — a computed probability
    cannot express "this read cannot be trusted".
  - probability: within ±10 points (direct) / ±2 points (code) of the
    calculator's P(B beats A); mean absolute error also reported.
  - problem-flagging: for the 9 items with a known problem (4 peeked,
    5 small-sample), whether the model's own words mention it
    (keyword match against a frozen list in `items.py`). This is a
    generous, mechanical check and is reported as one.
- **Model selection rule** (from the spec): two models from different
  families; the cheapest that answer all 5 pilot items in the required
  format. Pilot items: item01, item13, item20, item24, item28 (one per
  situation that matters). Pilot candidates were the cheapest
  serverless chat models on Together at the time (probed first with a
  one-call check; several catalog models turned out to be
  non-serverless on this account and were excluded by that probe, not
  by preference).
- **Pilot outcome** (5 items × 2 modes = 10 answers per model; format
  = the reply parses / the code runs and prints the required JSON):

  | model | family | format | note |
  |---|---|---|---|
  | openai/gpt-oss-120b | OpenAI | 10/10 | qualifies |
  | thinkingmachines/Inkling-2-Small | Thinking Machines | 10/10 | qualifies |
  | meta-models/Muse-Glimmer-30B | Meta | 9/10 | one code answer failed to run |
  | deepseek-ai/DeepSeek-V4.1-Flash | DeepSeek | 8/10 | two direct answers truncated |
  | nvidia/NVIDIA-Nemotron-3.5-Super-VL | NVIDIA | 6/10 | code + truncation failures |
  | arize-ai/qwen-2-1.5b-instruct | Qwen | 5/10 | direct fine; code answers broken |
  | zai-org/GLM-5.3-Flash | Zhipu | 4/10 | reasoning overran the token budget |
  | MiniMaxAI/MiniMax-M3.1-Flash | MiniMax | 3/10 | reasoning overran the token budget |
  | ricursive-ai/Ripple-65B-Preview | Ricursive | 3/10 | truncation + format failures |
  | Qwen/Qwen3.5-9B | Qwen | 0/10 | reasoning overran the budget on every call |
  | together/Tev1-4B-experimental | Together | 0/10 | serving cut every answer at 8 tokens |

  The dominant failure mode was not wrong statistics: it was
  reasoning-style models spending the entire token budget before
  producing an answer. The budget was therefore raised from 1,200 to
  4,000 tokens after the first pilot round and the pilot re-run for
  all models (round 1 is kept in `outputs/pilot_runs_v1.jsonl`).
  Models are scored on their final answer text only, never on a
  separate reasoning channel.
- **Selected models:** `openai/gpt-oss-120b` ($0.15 in / $0.60 out per
  1M tokens) and `thinkingmachines/Inkling-2-Small` ($0.30 / $1.00) —
  the two cheapest models that met the rule, from different families.
- **Main run:** 30 items × 2 modes × 2 models = 120 calls,
  temperature 0.7, max 4,000 tokens, per-call seeds derived from
  seed_base 20261112, resumable by run ID. Spend cap $3 total for the
  project, tracked in `SPEND.md` from returned usage at catalog
  prices.

## Tests that must pass

- Posterior quantities and P(B beats A) agree with a 600,000-draw Monte
  Carlo on three cases (small, check case, Cookie-Cats-sized).
- The one-look false-positive rate is 5% ± Monte Carlo error.
- The grid expected losses used by the simulator agree with exact
  quadrature; the grid calculator pack agrees with the exact formulas.
- The JavaScript calculator in the playground agrees with the Python
  calculator on fixed cases.
- Full suite: `.venv/bin/python -m pytest`.

## What would change the conclusions

- If the Bayesian stopping rule's false-positive rate did **not**
  climb with the number of looks at the frozen threshold, the summary
  would say the rule is safe to peek with at these settings — the
  simulation is run and reported either way.
- If both models ace the direct mode, the LLM check's conclusion is
  that these summaries are easy for current models, and the per-item
  breakdown (which categories fail, if any) is the result.
